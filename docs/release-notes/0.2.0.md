# msoutlook-mcp 0.2.0

Minor release: MIME fidelity and backlog pagination for consumers that rebuild
messages, plus continuation for both mail list tools.

```sh
mise use -g github:t128n/msoutlook-mcp@0.2.0
msoutlook-mcp setup
```

## What is new

- **Transport headers (#18).** `read_mail(include_transport_headers=true)` returns
  the verbatim `PR_TRANSPORT_MESSAGE_HEADERS` block (capped at 64 KiB), including
  `References`, `In-Reply-To` and the `Received` chain. Off by default and never
  logged.
- **Attachment fidelity (#19).** Attachments now carry `content_id`, `mime_type`
  and `is_inline`. `read_mail(attachments="base64")` returns bytes with per-part
  and per-response caps; skipped parts report `too_large`, `total_cap` or
  `unavailable`.
- **Pagination (#20).** `list_mail` accepts `sort: "newest" | "oldest"` and an
  opaque cursor. `search_mail` gains the same cursor. A cursor carries the
  `ReceivedTime` boundary and the EntryIDs already delivered, so shared-timestamp
  blocks drain without duplicates or gaps. Cursors are bound to their query and
  sort.

## Compatibility notes

- `read_mail` attachment metadata gains `content_id`, `mime_type` and `is_inline`
  in the default mode. Existing fields are unchanged.
- `transport_headers` and attachment bytes are opt-in. Base64 is capped at
  2 MiB per part and 8 MiB per response by default; the response can be about
  4/3 the byte size.
- `list_mail` and `search_mail` add `next_cursor` only on a capped page. A request
  with neither `sort` nor `cursor` keeps the previous newest-first response.

The Windows verification caveat still applies: real COM/Outlook, Task Scheduler,
the hidden launcher, rules/contacts and OpenCode event wake-up remain unverified
and are listed in `docs/windows-checklist.md`. Use a test mailbox first; sending
is off by default.
